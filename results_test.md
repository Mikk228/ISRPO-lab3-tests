## Лабораторная работа №4. Написание Unit-тестов

### 1. Цели и задачи тестирования

Цель работы — разработать и выполнить модульные тесты (Unit-тесты) для проверки корректности работы программы.

Основные задачи:
- проверить работу функций взаимодействия с базой данных;
- проверить добавление и удаление задач;
- проверить получение сохранённых данных;
- выявить возможные ошибки в работе программы.

### 2. Описание тестируемого продукта

Программа на языке Python, предназначенная для управления задачами с использованием базы данных SQLite.

Программа содержит следующие основные функции:

- `read_data()` — получение всех записей из базы данных;
- `addToBase()` — добавление новой задачи в базу данных;
- `remove()` — удаление задачи по идентификатору;
- `uploadingTasks()` — получение списка сохранённых задач.

Для взаимодействия с веб-интерфейсом используется библиотека Eel.

### 3. Область тестирования

В ходе тестирования проверялись следующие компоненты программы:

1. Получение данных из пустой таблицы.
2. Добавление новой задачи в базу данных.
3. Преобразование числовых параметров в целочисленный тип.
4. Получение всех сохранённых задач.
5. Удаление задачи по идентификатору.
6. Сохранение остальных записей после удаления одной задачи.

### 4. Стратегия тестирования

Для проверки программы использовалось модульное тестирование с применением стандартной библиотеки Python `unittest`.

Тесты были объединены в класс `TaskDatabaseTests`, который наследуется от `unittest.TestCase`.

Для проверки результатов использовались методы `assertEqual()`.

В качестве тестовой базы данных использовалась SQLite в оперативной памяти (`:memory:`). Это позволяет выполнять тестирование без изменения основной базы данных.

Также для библиотеки Eel была создана заглушка, позволяющая тестировать функции программы без запуска веб-интерфейса.

Перед каждым тестом таблица очищалась и создавалась заново. После завершения теста данные удалялись.

Тесты 7-9 не пройдены из-за ошибки в функции `remove()`. В строке `i = i[-1]` программа получает только последний символ переданного идентификатора вместо полного номера задачи.

В результате при удалении задач с двузначными номерами программа удаляет другие задачи, номера которых совпадают с последней цифрой идентификатора.

Тесты 10–13 проверяют ошибки при некорректном цвете и ID: программа выдаёт `IndexError` или `OperationalError`, потому что не проверяет входные данные.

### 6. Критерии приёмки

Программа считается успешно протестированной при выполнении следующих условий:

- все тестовые функции выполняются без ошибок;
- задачи корректно добавляются в базу данных;
- данные возвращаются в ожидаемом формате;
- числовые параметры преобразуются в целочисленный тип;
- удаление задачи не приводит к удалению остальных записей;
- фактические результаты совпадают с ожидаемыми.
